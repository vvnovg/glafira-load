# Проект и сервисы

Проект НТ описывает тестируемую систему: её сервисы, их контракты и стенды. В этой главе — вкладки
[[ui:sidebar.project]] и сервиса.

## Папка проекта {#folder}

[[ui:sidebar.newProject]] создаёт проект в пустой папке. Glafira не выполняет `git init`: положите папку в
существующий репозиторий или инициализируйте его сами. В папке лежат:

- `glafira-load.yaml` — манифест: имя проекта, сервисы и стенды;
- `registry/operations.yaml` — реестр операций ([Реестр операций](registry.md));
- `registry/scans/<дата-время>.yaml` — снимок каждого разбора, по ним строится дифф;
- `registry/tables/<сервис>.yaml` — таблицы и колонки из миграций сервиса;
- `load/prod-load.yaml` — цифры нагрузки ПРОМ ([Нагрузка ПРОМ](prod-load.md));
- `load/imports/<дата-время>.xlsx` — копия каждого импортированного шаблона;
- `load/profile.yaml` — коэффициенты и профили нагрузки ([Профиль нагрузки](profile.md));
- `.gitignore` со строкой `runs/` — результаты прогонов следующих этапов не попадают в git.

Коммитьте все эти файлы: это обычный YAML, отсортированный так, что `git diff` показывает только настоящие изменения.
Каждый файл записывается атомарно: сбой не оставит половину файла. Список открытых проектов хранится в настройках
приложения, а не в проекте. Проект, папка которого пропала, остаётся в левой панели серым; [[ui:sidebar.remove]]
убирает его из списка.

[[ui:project.openFolder]] показывает папку в файловом менеджере.

## Сервисы {#services}

Сервис — локальный клон git одного компонента тестируемой системы. Нажмите [[ui:project.addService]] на вкладке
проекта, введите [[ui:project.serviceId]] (строчные латинские буквы, цифры и дефис, уникален в проекте) и
[[ui:project.serviceName]], выберите папку клона и нажмите [[ui:common.save]]. Папка внутри проекта записывается в
манифест относительно него, любая другая — абсолютным путём; манифест можно поправить вручную и написать, например,
`../orders-service`.

На вкладке сервиса видна версия клона: `git describe --tags --always --dirty` и коммит. Версия попадает в реестр,
поэтому видно, в какой версии появилась операция. Если `git` не установлен или папка не репозиторий, версия —
`unversioned`, на вкладке появляется предупреждение; разбор при этом работает.

**Контракты.** Если в манифесте у сервиса нет списка контрактов, Glafira ищет их в клоне по маскам и пропускает
`.git`, `node_modules`, `target`, `build`, `dist`, `vendor`, `.idea`, `.gradle` и файлы из `.gitignore` самого клона
(`.gitignore` папок выше клона и ваши глобальные исключения git не действуют):

| Вид | Маски |
|---|---|
| `openapi` | `**/openapi*.{yaml,yml,json}`, `**/swagger*.{yaml,yml,json}`, `**/api-docs*.json` |
| `proto` | `**/*.proto` (пути импорта — папки найденных файлов) |
| `asyncapi` | `**/asyncapi*.{yaml,yml,json}` |
| `schema` | `**/*.avsc`, `**/*.schema.json` |
| `sql` | `**/db/migration/**/*.sql`, `**/migrations/**/*.sql`, `**/db/changelog/**/*.{xml,yaml,yml,sql}`; откатные миграции пропускаются |
| `spring` | `**/src/main/java/**/*.java`, `**/src/main/kotlin/**/*.kt`, только если в клоне есть `pom.xml` или `build.gradle*` |

Выключение найденного контракта записывает в манифест весь список контрактов, у выключенного — `enabled: false`:
с этого момента список фиксирован, новые файлы добавляются кнопкой [[ui:service.addContract]] или находятся заново
кнопкой [[ui:service.discover]]. Путь контракта — относительно клона и не может выходить за его пределы.

**Топики Kafka.** В разделе [[ui:service.kafkaTopics]] топику сопоставляется файл его схемы (`.avsc`, JSON Schema).
Без сопоставления топик файла схемы угадывается по имени файла, и реестр помечает такие операции.

**Разбор.** [[ui:service.scan]] разбирает контракты сервиса в фоне с прогрессом по файлам; его можно отменить, и
отменённый разбор ничего не записывает. [[ui:project.scanAll]] на вкладке проекта разбирает все сервисы по очереди.
В отчёте — сколько операций найдено, сколько новых, изменённых, удалённых и вернувшихся, а также предупреждения и
ошибки по файлу и строке; [[ui:service.openFile]] открывает файл в приложении, которое назначено для него в системе. Ошибка в одном контракте не
останавливает остальные: сервис получает операции из разобранных файлов. Если контракты найдены, но ни один не
разобран, реестр не меняется (иначе все операции сервиса стали бы удалёнными), и отчёт об этом сообщает. Файл
контракта больше 32 МиБ — ошибка этого файла, он пропускается. Если [[ui:project.scanAll]] споткнулся на одном
сервисе, отчёты остальных сервисов сохраняются. В проекте одновременно идёт один разбор.

## Стенды {#environments}

Стенд — тестовое окружение, где будет идти нагрузка: [[ui:project.envId]], [[ui:project.envKind]] (`dev`, `test`,
`stage` или `prod`) и адреса: [[ui:project.env.http]], [[ui:project.env.kafka]],
[[ui:project.env.grpc]] и [[ui:project.env.sql]]. Вид показан бейджем рядом с выбором, `prod` — красным, чтобы стенд
ПРОМ не спутать с тестовым; в версии 0.1.0 бейдж есть только на вкладке проекта. Адреса пишите без паролей: манифест
коммитится в git. Секреты
появятся вместе с раннером на этапе L2; в этой версии стенды только описываются.

## Проблемы манифеста {#problems}

Если манифест нарушает правила (пустое имя, плохой или повторяющийся ID сервиса или стенда, сервис без папки,
неподдерживаемый формат), проект открывается только для чтения: баннер на вкладке проекта перечисляет проблемы,
сохранение, разбор, импорт и ручные правки недоступны. О манифесте, который не является корректным YAML, приложение
сообщает с файлом и ошибкой. Исправьте `glafira-load.yaml` в редакторе и откройте проект заново. Неизвестные поля манифеста
сохраняются, когда Glafira его перезаписывает, поэтому поля следующих версий и ваши пометки не теряются.
