# Агенты и стенды

Нагрузку создают агенты — копии CLI `glafira-load`, запущенные на машинах нагрузки стенда. Приложение (или
`glafira-load run --agents`) выступает контроллером: отправляет каждому агенту сьют и долю профиля, получает метрики
потоком и собирает папку результата на машине инженера. Без агентов нагрузка идёт в процессе самого контроллера:
прогон на стенде без агентов — внутри приложения, `glafira-load run` без `--agents` — в CLI; этого достаточно для CI и
одной машины.

## Установка агента {#install}

CLI — один статический бинарник на платформу, публикуется рядом с установщиками:
https://github.com/vvnovg/glafira-load-releases/releases. Экран [[ui:sidebar.about]] показывает команду скачивания
для операционной системы и процессора текущей машины; имена файлов — `glafira-load-linux-x86_64`,
`glafira-load-linux-aarch64`, `glafira-load-macos-aarch64`, `glafira-load-macos-x86_64` и
`glafira-load-windows-x86_64.exe`, рядом с каждым — файл `.sha256`. Положите бинарник в `PATH`, проверьте его командой
`glafira-load --version` и запустите агента:

```bash
glafira-load agent --listen 0.0.0.0:7420 --token-file ~/.glafira-load/token \
                   --work ~/.glafira-load/agent --keep-runs 10 --drain-ms 5000
```

Состояние агента — в памяти и в `--work` (по умолчанию папка `glafira-load-agent` во временной папке системы): бандлы
и файлы прошлых прогонов, из которых хранятся последние `--keep-runs` (по умолчанию 10). `--drain-ms` — сколько идущие
итерации могут дорабатывать после остановки (по умолчанию 5000). Один агент исполняет один прогон за раз; `Ctrl+C`
останавливает текущий прогон, а затем агента. Запуск агента системной службой (systemd, launchd, служба Windows)
описан в руководстве администратора в репозитории (`docs/admin.md`).

Версии приложения и агента должны совпадать в мажорной и минорной части (`0.2`), а `format` сьюта должен быть известен
агенту; иначе прогон не стартует с ошибкой `AGENT_VERSION`, и в строке агента видны обе версии.

## Токен {#token}

Каждый запрос к агенту несёт bearer-токен. Агент берёт его из `--token`, `--token-file` или переменной окружения
`GLAFIRA_LOAD_AGENT_TOKEN`, в этом порядке, и без токена не стартует. Сгенерируйте длинную случайную строку, например
`openssl rand -hex 32`, и отдайте её агенту и приложению.

Приложение хранит токены в хранилище секретов операционной системы (Keychain, Credential Manager, Secret Service),
никогда в манифесте. Токен вводится в поле токена строки агента на вкладке проекта и сохраняется кнопкой
[[ui:agents.saveToken]]; [[ui:agents.removeToken]] удаляет его. Токен задаётся только агенту сохранённого манифеста:
сначала сохраните новую строку агента, а токен сохраните до следующего сохранения манифеста — сохранение манифеста
очищает введённый, но не сохранённый токен. Токены хранятся по папке проекта, стенду и агенту; если папку проекта
переместить или переименовать, токены нужно ввести заново.

`glafira-load run --agents` читает токены из `GLAFIRA_LOAD_AGENT_TOKEN_<ID>`, где `ID` — ID агента в верхнем регистре
с `-`, заменённым на `_` (`gen-1` → `GLAFIRA_LOAD_AGENT_TOKEN_GEN_1`). Агент без токена помечен как
[[ui:agents.state.no_token]], и прогон не стартует с `TOKEN_MISSING`; неверный токен — ответ 401 от агента, он показан
в его строке.

## Секреты стенда {#secrets}

Сьюты ссылаются на секреты как `{{secret ИМЯ}}` и перечисляют их в `secrets`. Значения живут только в окружении
агентов: `GLAFIRA_LOAD_SECRET_<ИМЯ>`. Приложение их не хранит и не передаёт; контроллер отправляет только список имён,
а агент, у которого какого-то нет, отказывается от прогона с `SECRET_MISSING` и именами — они показаны в баннере. В
примерах ошибок значения секретов заменены на `***`.

Смок и прогон на стенде без агентов идут внутри приложения или CLI, поэтому там переменные нужны в их собственном
окружении: задайте их в оболочке перед `glafira-load run` или `glafira-load smoke` и запускайте приложение из
терминала, в котором они заданы.

## Стенд с агентами {#stand}

Агенты принадлежат стенду манифеста ([Проект и сервисы](project.md#environments)). На вкладке проекта у стенда
появляется адрес [[ui:project.env.schema_registry]] (нужен для `encoding: avro`) и таблица [[ui:agents.title]]:
[[ui:agents.id]], [[ui:agents.url]], [[ui:agents.weight]] и токен. [[ui:agents.add]] добавляет строку.
В файле:

```yaml
environments:
  - id: test
    kind: test
    http: https://orders.test.local
    kafka: kafka-1.test.local:9092
    schema_registry: https://sr.test.local
    agents:
      - { id: gen-1, url: http://10.0.1.11:7420 }
      - { id: gen-2, url: http://10.0.1.12:7420, weight: 2 }
```

ID агента уникален в стенде. URL — `http://` внутри сети стенда; `https://` принимается, когда агент стоит за обратным
прокси с сертификатом, которому доверяет система. Своего TLS у агента в этой версии нет. Стенд без агентов допустим:
прогон на нём идёт внутри приложения.

## Веса {#weights}

Контроллер делит цели профиля по весам: агент с весом 2 рядом с агентом с весом 1 получает две трети каждой цели и две
трети строк каждого набора `slice`. Вес по умолчанию 1 и не меньше 1. Он нужен, когда машины нагрузки разного размера,
или чтобы для пробы запустить двух агентов на одной машине.

## Проверка агентов {#probe}

[[ui:agents.probe]] на вкладке проекта (для агентов сохранённого манифеста) и строки агентов в окне прогона
спрашивают у каждого агента версию, операционную систему, процессор, число ядер и занят ли он. Состояния:
[[ui:agents.state.ready]], [[ui:agents.state.busy]] (с ID прогона, который он исполняет),
[[ui:agents.state.unreachable]] (нет ответа, причина в строке), [[ui:agents.state.version]] (обе версии в строке) и
[[ui:agents.state.no_token]]. При старте прогона контроллер спрашивает агентов ещё раз: прогон не стартует, если
какой-то агент недоступен, занят, другой версии или без токена.

## Обрыв агента {#loss}

Агент отдаёт метрики потоком раз в секунду; контроллер помнит позицию потока и после обрыва переподключается до
30 секунд, продолжая с последнего события (агент буферизует две минуты). Если агент не вернулся, его строка становится
[[ui:run.agentState.lost]], прогон продолжается на остальных агентах, а статус итога —
[[ui:run.runStatus.incomplete]]. По окончании прогона контроллер просит потерянного агента остановиться и ещё раз
запрашивает его файлы; если агент к тому времени вернулся, они собираются.

Закрытие приложения во время прогона спрашивает, что делать: [[ui:run.close.stop]] останавливает прогон, ждёт, пока
папка будет записана, и закрывает окно; [[ui:run.close.leave]] закрывает сразу, а агенты дорабатывают таймлайн сами и
хранят файлы. Когда прогон идёт внутри приложения (смок или стенд без агентов), вторая кнопка —
[[ui:run.close.leaveInside]]. Этот вопрос показывают кнопка закрытия окна и `Cmd+Q` на macOS; выход через Dock и выход
из сеанса macOS показать его не могут — тогда прогоны останавливаются в пределах 3 секунд.

При следующем открытии проекта прогон виден в разделе [[ui:run.past.title]] как [[ui:run.past.inProgress]]; список
запрашивает у агентов их файлы и достраивает папку — со статусом [[ui:run.runStatus.incomplete]], если до кого-то не
дозвался или файлы уже удалены по `--keep-runs`. Прогон, который агент ещё исполняет, остаётся незавершённым, пока
агент не закончит.
