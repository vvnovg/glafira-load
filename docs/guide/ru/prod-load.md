# Нагрузка ПРОМ

Профиль нагрузки начинается с реальных цифр: сколько запросов в секунду получает каждая операция на ПРОМ. Glafira
выгружает операции в Excel-шаблон, команда с доступом к мониторингу ПРОМ его заполняет, и вы импортируете его обратно.
Цифры хранятся в `load/prod-load.yaml`. Вкладка открывается пунктом [[ui:sidebar.prodLoad]] в левой панели.

## Шаблон {#template}

Нажмите [[ui:prodLoad.export]] и выберите, куда сохранить файл; предлагаемое имя — `prod-load-<проект>-<дата>.xlsx`.
Если включено [[ui:prodLoad.prefill]], в шаблоне уже стоят цифры последнего импорта, и команде остаётся их обновить.
Шаблон пишется на языке интерфейса в момент выгрузки.

В шаблоне три листа. На листе **Операции** — строка на каждую активную операцию реестра. Колонки A–E (ID, сервис, тип,
операция, описание) защищены: лист защищён без пароля, чтобы уберечь их от случайной правки. Заполняются колонки F–L:

| Колонка | Что вписать |
|---|---|
| F, среднее RPS | число ≥ 0; обязательно, если в строке есть хоть одна цифра |
| G, пиковое RPS | число не меньше среднего; пусто — то же, что среднее |
| H, доля ошибок, % | от 0 до 100 |
| I, размер запроса, байт | целое ≥ 0 |
| J, размер ответа, байт | целое ≥ 0; для строк Kafka оставьте пустой |
| K, p95 ПРОМ, мс | число ≥ 0 |
| L, комментарий | любой текст |

У строк `kafka_consume` цифры значат другое: F и G — сообщений в секунду, I — размер сообщения, K — допустимый лаг
потребителя в секундах. Excel проверяет числа при вводе; у заголовков колонок есть примечания с этими правилами.
В версиях 0.1.0 и 0.2.0 колонка J у строк Kafka не защищена: оставляйте её пустой — введённое значение импортируется как есть.

На листе **Параметры** в ячейке A1 — маркер проекта (не меняйте его) и поля о цифрах: стенд ПРОМ, период наблюдения,
система мониторинга, из которой они взяты, и кто их заполнил. Лист **Справка** повторяет эти правила для того, кто
заполняет шаблон.

## Импорт {#import}

Нажмите [[ui:prodLoad.import]] и выберите заполненный файл (до 32 МиБ). Сначала Glafira проверяет маркер на листе «Параметры»:
шаблон другого проекта или формата отклоняется с ожидаемым и найденным маркером. Затем показывается предпросмотр:

- **заполненные** — строки с цифрами, сопоставленные с реестром по ID;
- **пустые** — строки без цифр; у этих операций остаются прежние цифры;
- **неизвестные ID** — строки, ID которых нет в реестре, например из старого шаблона; они пропускаются;
- **с ошибками** — строка, колонка, значение и проблема: не число, отрицательное, не целое, процент вне 0–100, пик
  меньше среднего или нет среднего.

В предпросмотре также видны значения листа «Параметры» и дифф по каждой операции: [[ui:prodLoad.before]] и
[[ui:prodLoad.after]]. Пока есть хоть одна строка с ошибкой, кнопка [[ui:prodLoad.apply]] недоступна: исправьте файл и
импортируйте его снова. [[ui:prodLoad.apply]] записывает `load/prod-load.yaml` и сохраняет копию импортированного файла
в `load/imports/<дата-время>.xlsx`, чтобы всегда было видно, откуда взялись цифры.

После импорта на вкладке видны текущие цифры с датой и стендом импорта и число активных операций, у которых цифр ещё
нет.

## Файл load/prod-load.yaml {#file}

```yaml
format: 1
source:
  stand: prod-msk
  period_from: 2026-10-01
  period_to: 2026-10-14
  system: Grafana
  filled_by: Иванов
  imported_at: 2026-10-31T12:00:00Z
  file: load/imports/2026-10-31-120000.xlsx
operations:
  "http:orders:POST /v1/orders": { avg: 120, peak: 340, error_pct: 0.2, req_bytes: 850, resp_bytes: 420, p95_ms: 180 }
  "kafka_consume:orders.created": { avg: 110, peak: 300, req_bytes: 1200, lag_max_s: 5 }
```

`avg` и `peak` — запросов в секунду (сообщений в секунду у `kafka_consume`); `error_pct`, `req_bytes`, `resp_bytes`,
`p95_ms` и `comment` записываются, если заполнены; `lag_max_s` — допустимый лаг операций `kafka_consume`. Файл можно
править вручную; следующий импорт заменит цифры тех строк, которые в нём заполнены.
